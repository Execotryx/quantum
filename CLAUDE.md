# Project guidance

The Codex operations plugin in `plugins/quantum-operations` uses a separate frozen
MCP environment and the existing project environment for Linux jobs. Preserve
credential-free startup, previewable cloud actions, durable process identities,
and explicit review of backend path relocation. See `docs/quantum-operations-plugin.md`.
Keep `tools/provision-quantum-cloud.sh` aligned with the plugin's VM configuration
and test its preview and rerun behavior with a mocked CLI.

The inverse-square-root screen lives in `tools/invsqrt_opportunity.py`. Preserve
the preregistration, all lane outcomes, and separate full and confirmation receipts.
Receipt preparation binds the local certificate, archive and published metric
hash. Keep score receipts immutable and distinguish capped fits from measured
exclusion decisions.
The direct-phasing v3 screen in `tools/invsqrt_direct.py` compares individual
changes against the confirmed v2 bytes before combining gains.
The v4 lattice recipe pins both single-width parents and the exact winning
table. Keep model-only two-octave pricing separate from native circuit costs.
The trimmed-width recipe requires full-domain intermediate bounds and
v4 phase identity before its separate promotion campaign.
The v6 sibling-control screen keeps v5 as its byte-identical control and
requires two matching builds and agreement with the complete cost model.
Use the calibrated direct stage model within its documented format and
scope. A modeled resource improvement still needs the candidate gates.

On the combined optimization branch, `tools/banked_chemistry.py` screens the
lookup-only replacement and tests the extracted combined archive. Preserve the
pinned numerical inputs and separate chemistry confirmation evidence.
Run the continuous residual gate in `tools/chem_shape_search.py` before ANGLE
synthesis. Keep the tower-field DQI receipts from `tools/dqi_decoder_screen.py`
scoped to the decoder dimensions they actually exercise.
The DQI stage profiler reconciles the reference KMB and native counts.
Keep standalone phase scans, inverse primitives and classical end-state
proofs separate from complete decoder verification. Keep synthetic
compressed ANGLE results separate from a fitted chemistry family.
Treat an I3 checkpoint restart as a separate run and a loader reference
control as development evidence.
Use the bounded grid supervisor for registered fit plans. Keep timeouts,
worker failures and completed lanes in separate immutable attempts.
The alternating-projection fit gates decoding on continuous residual. Register
S2 settings before projecting complete loader cost for every passing lane.
Use the one-contingency S2 supervisor before preparing S3 and the release loader.
Circular DQI rounds increment the counter on zero discrepancy. The routed
decoder needs a passing freed-nonzero probe and registered history depth.
An overflow leaves a verifier-visible count and bypasses exact history pops.
Use `tools/hybrid_certification.py` for the audited parent and successor
certificate. Keep chemistry's one-use confirmation scoped to the complete
family and NPZ. Resolve inherited evidence through the trusted parent record.
The `review-backend` action compares original hash-bound verifier requests
across relocated source checkouts and records their distinct identities.
Pin confirmation backend snapshots in the frozen protocol and keep
legacy coverage checks separate from candidate-v1 lineage.
For a reviewed standalone inverse-square-root confirmation, keep the
original screen, full pass, fresh confirmation and archive receipts separate.

Step-3 tools under `tools/` bind differential and primitive evidence to pinned
upstream hashes. Keep fixture coverage and expected mutation diagnostics explicit.

Follow `AGENTS.md` for contract provenance, measured gate boundaries, official DQI
failure-counter mappings, Python 3.13/WSL validation and dated change logs.

Baseline campaigns additionally require clean committed source, preregistered
A,A,B salts, an external process-tree sampler, and verified deterministic bundles.
See `docs/baseline-campaign-02-11-2026-01-19-10.md` for measurement definitions.
