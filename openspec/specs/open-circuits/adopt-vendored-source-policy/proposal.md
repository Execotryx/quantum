## Why

The repository has allowed independently generated circuits only. Public
Apache-2.0 circuits that ship their generating source are 4–18× ahead on
each task:

| Task | Public ratio | Ours |
| --- | ---: | ---: |
| invsqrt | ≈ 20.7 | 5.05 |
| DQI | ≈ 63 | 3.46, routed, unarchived |
| Chemistry | ≈ 10.6 | 1.03 |

The owner approved relaxing the policy to **"vendored, pinned, credited
source, regenerated by our pipeline."**

The competition's winner licence is Apache 2.0, and it covers the submission
and its generating code. The repository has no `LICENSE` file today, so
vendoring Apache-2.0 code without one leaves the licence state undefined.

## What Changes

- **Apache 2.0 licence text as a distinct file.** Add the complete,
  unmodified text of the Apache License, Version 2.0, as a separate file
  `LICENSE` at the repository root. It is not pasted into any other file.
  `pyproject.toml` references it.
- Add a root `NOTICE` file and a `third_party/` tree with one directory per
  vendored component. Each directory holds the upstream licence, the upstream
  notice if any, a provenance record and the unmodified upstream files.
- Replace the independent-generation-only rule in `AGENTS.md` and `CLAUDE.md`
  with the vendored-source rule and its admission checks.
- Add a `third_party` check to the existing test suite.

## Impact

- Every later change in this set (`vendor-public-c40-chemistry`,
  `vendor-public-inplace-dqi`, `vendor-public-62q-invsqrt`) requires this one.
- The repository's own code becomes Apache-2.0-licensed through the root
  `LICENSE`. This matches the competition's winner licence.
- Existing evidence, receipts and member hashes are unchanged.
