# GF(8)-subtower inverse

Implemented a clean XOR inverse for GF(4096), retaining the pinned `0x1053` polynomial-basis input and output and mapping zero to zero. The GF(64) norm is computed in the existing outer tower, then inverted through a quadratic GF(64)/GF(8) subtower. The three-bit GF(8) inverse is the quadratic map `x^6`, evaluated with three temporary ANDs and linear CNOTs. The computed GF(8) and GF(64) norm products are erased by X-basis measurement with tensor-derived, outcome-conditioned CZ corrections; square terms are first removed by linear maps. Shared phase-repair code handles all three field widths.

The cost breakdown is 18 Toffoli-like gates for the outer norm product, 24 each for computing and uncomputing the GF(64) inverse, and 36 for the two final products: **102**, at 63 declared qubits and 7 classical bits. The previous tower inverse used 180; this clears the planned at-most-110 primitive gate. The circuit receipt and KMB hash are in `docs/evidence/dqi-subtower-inverse-20261108/slice.json`; an emission took 3.88s and 39,772 KiB single-process peak RSS including Python startup. After the simplicity refactor, the serialized circuit hash was identical.

Native tests compared all 4,096 inputs, including zero, with an independently implemented polynomial-field inverse, using nonzero randomized target words. Two successive applications restored every input and target with no phase changes or dirty scratch. Separate GF(8) and GF(64) product-erasure tests cover all operand pairs and detect a deliberately dropped CZ. GF(8) product truth tables are also checked against the pinned field. Nine focused WSL tests, Ruff and Pyright passed. The primitive result does not establish complete locator, phase-scan assembly, DQI acceptance, full-size cost or confirmation.
