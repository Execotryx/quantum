# Branch proof for temporary AND cleanup

The pinned inverse-square-root builder uses a temporary product in `_add_row`.
The following proof states the interface that `init_and` and `del_and` must
realize for that use. Native instruction conformance is a separate check.

Let the two control bits be a and b, and let f = ab. Scratch starts in
|0⟩. Assume computation maps |a,b,0⟩ to |a,b,f⟩ with no relative phase.
Between computation and erasure, allow any controlled operation U_f on
the target, preserving a, b, and f. The target may include an entangled
reference. For an arbitrary input sum over a,b with target vectors v_ab,
the resulting target vectors are U_f v_ab.

An X-basis scratch measurement with outcome m contributes the scalar
⟨m_X|f⟩ = (−1)^(mf)/√2 to each term. Conditional CZ on the controls for
m=1 contributes (−1)^(mab). Their product is 1/√2 for every a,b,m.
Mapping the measured scratch eigenstate to |0⟩ then gives the same
corrected logical operation in either branch. Each branch has probability
1/2 for normalized input. The controls retain their labels and all
relative phases, and scratch is separable and reusable. Linearity covers
arbitrary superpositions and target entanglement.

For composition, applying another operation V to the logical registers
gives branch vectors V U_f v_ab with the same common scalar. Iterating
with fresh or reset scratch multiplies those common scalars. This applies
to the controlled add/subtract in the row builder when its implemented
gates satisfy the assumed interface.

Omitting conditional CZ leaves a relative minus on |11⟩ for m=1.
With controls (|00⟩+|11⟩)/√2 and identity target action, inverse Bell
preparation (CNOT then H on the first control) yields |10⟩ instead of
|00⟩ in that branch. A computational-basis register comparison before
inverse Bell preparation cannot distinguish the two phases. This gives
a concrete detector and expected diagnostic for the native mutation run.
