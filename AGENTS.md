# Project instructions

- The Codex operations plugin under `plugins/quantum-operations` delegates project
  commands; keep its catalog synchronized with the CLI. Its MCP dependency lock
  is separate from the scientific lock. Test its actual stdio protocol and Linux
  job lifecycle, including detached descendants and reconnects. Cloud actions
  preview by default; keep account settings ignored and credentials out of tool
  arguments. Relocation proposals must not silently rewrite pinned evidence.
- Review archived backend requests through their original receipt hashes.
  A path-only inventory comparison keeps both original identities and
  leaves the separate release lineage and confirmation gates in force.
  Pin a separately located confirmation inventory in its protocol before
  reserving the salt.
- A reviewed standalone inverse-square-root confirmation binds both
  full receipts, the original screen, backend, circuit and confirmation
  salt. Use the complete extracted-archive metric for release acceptance.
- Keep the Cloud Shell provisioner's resource defaults and JSON output aligned
  with the operations plugin. Verify preview and rerun behavior without cloud writes.
- Inverse-square-root opportunity screens freeze the protocol before simulation,
  run the reference control first, and retain each parallel lane separately.
  Full verification and fresh confirmation must use the same frozen KMB bytes.
- Direct-phasing screens on the hybrid branch also reproduce the confirmed
  Newton incumbent and price the complete declared-width and rotation cost.
  Keep public-source reproduction distinct from an independently generated
  circuit, and preserve the parent chemistry and DQI member hashes.
- The v3 direct-phasing screen checks each ablation independently before
  combining improvements. Restore coefficient-lookup phase after measurement
  and verify the padded lane and scratch on the serialized circuit.
- The v4 screen pins the lattice tables, requires each precision parent to
  pass and improve independently, and binds the winning KMB through full
  verification, fresh confirmation and the paired archive. Price projected
  widths and standalone address mappings separately from emitted circuits.
- The trimmed-width inverse-square-root recipe proves every intermediate
  fits and every phase matches v4 before using narrowed registers.
  Run the control first and preserve the exact emitted KMB for confirmation.
- Use the calibrated direct cost model only for its supported uniform
  dyadic architecture. Unseen formats need fresh phase and native gates.
- Keep tower-field DQI development receipts scoped to their actual code
  dimensions. Run the chemistry continuous residual gate before emitting
  decoded words or ANGLE circuits.
- Keep profiled reference stages, standalone phase-scan results and
  routed-decoder acceptance as separate evidence. A primitive receipt
  cannot close a decoder or archive gate. For joint chemistry fits,
  compare exact checkpoint residuals and leave a capped lane eligible
  for a separately registered continuation.
- A chemistry continuation pins the parent decision, checkpoint and target
  and starts a fresh optimizer. The registered loader runner distinguishes
  reference controls and eligible S3 handoffs from full chemistry acceptance.
- Validate every fit plan through the pinned grid manifest before a batch.
  Keep separate attempt receipts and resume only hash-verified completions.
- A floating-point fixed-basis relaxation supplies diagnostic evidence.
  Shape exclusion needs a certified bound for the variable basis.
- The sibling-control screen uses the frozen trimmed v5 KMB as its control.
  Require two matching v6 builds and agreement with the complete cost model.
- Alternating-projection chemistry lanes bind the start and terminal checkpoint.
  Require the continuous gate before decoding. Preregister S2 settings from the
  pinned reference before projecting costs for every passing lane. Bind the
  selected lane and run its S2 plan under the one-contingency supervisor.
  Projected loader costs cannot substitute for S3 accuracy or confirmation.
- Circular routed DQI rounds increment the counter on zero discrepancy. Gate
  decoder emission on the freed-nonzero verifier probe and complete registered
  depth campaign. Restore tagged entries on clean inputs and retain the
  overflow count as verifier-visible scratch on overflowed inputs.
- Banked chemistry lookups preserve the pinned factorization and angle words.
  Check the 128-qubit cap and phase, selection and workspace at every circuit
  boundary. Combined validation keeps the exact confirmed inverse-square-root
  bytes and reference DQI and verifies the extracted archive with the pinned metric.
- Hybrid certification requires a separate, one-use confirmation per generated
  benchmark. The chemistry scope includes the retained NPZ. A successor may
  carry forward byte-identical optimized chemistry only through the trusted
  parent certificate and its intact confirmation. Check the exact full
  coverage and retained costs before attributing a gain to inverse square root.
- New hybrid candidates opt into `candidate-v1`. Derive full chemistry coverage
  from the frozen NPZ shape, bind all retained component bytes to the certified
  parent, and use a matched parent replay if retained DQI observations differ.
  Keep paired development salts out of the confirmation ledger. Treat
  `hybrid_preflight.py` and the DQI primitive slices as structural development
  evidence. Keep the v2 inverse-square-root screen separate from v1 replay.

- Step-3 differential tools pin upstream/native hashes and retain explicit fixture
  coverage. Primitive evidence must state initialization, phase and composition
  assumptions and record expected mutation diagnostics before closing gates.

- Official verifier sources are authoritative; record file hashes and defining
  symbols in `contracts/contract.json`, including supplementary sources for
  imported constants or cross-file conventions.
- Resolved critical discrepancies require unchanged pinned evidence and an
  explicit resolution. Preserve per-benchmark receipts separately from the final
  metric completion report; a component receipt does not prove overall acceptance.
- A source-reconciled specification is not evidence of full baseline acceptance.
  Preserve unresolved measured gates until complete actual verifier results exist.
- DQI failure counts are the sum of disjoint `value_errors` and `phase_errors`.
  Backend confirmation mappings may use a list of distinct source counter paths.
- Run Pyright on changed Python files and run relevant tests in Ubuntu WSL with
  Python 3.13 for the supplied Linux kickmix binary. Use the frozen dependency lock.
  For the isolated environment, pass `--pythonpath vendor/linux-env/bin/python`
  to Pyright instead of relying on automatic environment discovery.
- Preserve dated Markdown change logs under `docs/`; use OpenSpec for plans.
- Receipt preparation checks the published metric hash and binds the exact
  local certificate, ZIP and message. Keep external observations immutable
  and record corrections separately. Reserve DQI confirmation salts for
  their frozen component and classify capped fits from their objective trace.
- Step-2 campaigns require clean committed Linux source and frozen dependencies.
  Preregister A,A,B baseline salts and run serially at full strength; never reuse
  them as candidate confirmation. Profile by delegation to pinned upstream code.
- Keep the resource sampler outside the forking verifier worker. Report sampled
  process-tree PSS separately from summed RSS, with sampling/race limitations.
  Budgets include explicit measured headroom, not claims of minimum hardware.
- Frozen baseline bundles retain raw records and original inputs by hash, include
  one original archive rather than duplicate per-run input copies, and verify
  independent deterministic builds plus a clean Git source-bundle restore.
